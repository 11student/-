# 智慧教育课程平台团队分工方案

> 版本：0.1　日期：2026-10-21　状态：岗位待认领

本方案用于在正式开发前明确责任、交付物和审核关系。团队人数与成员名单尚未确定，因此先按岗位分工；一个人可以兼任多个岗位，但每项任务只设一名直接负责人，关键变更由其他成员独立审核。当前项目仍处于架构准备阶段，若依基础工程和教学业务代码尚未接入。

## 1. 分工原则

1. **任务有负责人。** 每个 Issue 记录需求来源、直接负责人、协作者、审核人、交付物和验收条件。岗位不等于固定人数。
2. **对象有归属。** 课程与教学班授权、课堂状态、提交与成绩、统计和 AI 建议分别由对应领域维护；跨领域通过评审后的服务或接口协作。
3. **先评审范围，再承诺交付。** 原需求的 P0/P1/P2 与新方案的 M0/M1/M2 是两套分级。同步课堂、自建课程和部分 AI 能力的首版范围由项目负责人组织确认。
4. **审核与实现分开。** 跨领域变更由相关领域共同审核；权限、正式成绩和数据库结构由相应责任岗位复核。作者不独自批准自己的关键变更。

## 2. 平台与交付岗位

| 责任岗位 | 负责范围 | 首批交付物 | 主要协作与审核 |
| --- | --- | --- | --- |
| 项目与产品负责人 | 首版范围、需求追踪、优先级、验收场景、变更决定；维护正式文档和原型入口 | 范围决定记录、需求到任务映射、验收清单 | 各领域、测试与交付 |
| 技术负责人 | 若依来源与版本、模块装配、身份安全、依赖方向和总体技术方案 | 上游选型记录、可构建的基础工程、权限设计评审 | 后端各领域、前端、数据库 |
| 前端负责人 | 一套前端工程中的教师、学生、管理员页面；复用登录、路由、权限和请求能力 | 三端导航、首条业务链路、接口联调记录 | 产品、对应业务领域、测试 |
| 数据库负责人 | 实体归属、快照、唯一约束、迁移与回退、数据访问和保留规则 | 数据模型、迁移脚本、验证与回退记录 | 各业务领域、技术负责人 |
| 测试与交付负责人 | 权限、状态、并发、断线恢复、真实设备和试点验收；建设必要的自动检查与发布记录 | 验收案例、测试矩阵、自动检查、试点与回滚记录 | 产品、技术负责人、领域负责人 |

## 3. 教学业务领域岗位

下列五个岗位覆盖规划中的九个教学领域。领域负责人维护对象模型、业务规则、接口、相关文档和验收案例；不把同一对象的写入权拆给多个岗位。

| 领域岗位 | 负责包 | 核心责任与首批交付 | 主要协作 |
| --- | --- | --- | --- |
| 课程与资源负责人 | `course`、`resource` | 课程空间、教学班成员与授权；资源、题目和版本发布。先打通教师建课、关联授权班级、学生访问授权资源 | 基础身份、备课、课堂、前端、数据库 |
| 教学过程负责人 | `prepare`、`classroom`、`activity` | 备课与预习、课堂会话和公开页状态、签到与随堂题；明确模板与实例、重连及并发规则 | 课程资源、作业、前端、测试 |
| 评价与学习负责人 | `assignment`、`learning` | 课堂小作业和课后作业共用提交、批改与正式评价；错题、补学和历史证据可追溯 | 活动、AI、学情、前端、数据库 |
| 学情统计负责人 | `analysis` | 定义指标分母、时间窗口、来源快照和权限范围；提供可追溯统计，不改写正式成绩 | 上游领域、产品、数据库、测试 |
| AI 适配负责人 | `ai` | 备课建议、答疑、初评任务的权限、版本、结果和失败回退；建议经业务方确认后使用 | 备课、作业、资源、技术负责人 |

### 关键交接边界

- `course` 和 `resource` 提供归属、成员资格、可见性与资源版本契约；其他领域不得直接访问其私有表。
- 课堂结束、模板激活和课堂小作业由入口用例编排；`classroom`、`activity`、`assignment` 共同评审状态、幂等和提交边界。
- 前后端在编码前共同确认字段、对象权限、错误、时间和重试语义；数据库负责人核对唯一约束与版本策略。
- 正式成绩须由教师确认发布。AI 初评、未公布答案和教师私有备注不得进入学生端或公开投影。

## 4. 人员认领表

团队名单确定后，由项目负责人填写。兼任岗位时，应为该岗位的关键变更安排另一位审核人。

| 岗位 | 负责人 | 协作者或备份 | 独立审核人 |
| --- | --- | --- | --- |
| 项目与产品 | 待指派 | 待指派 | 待指派 |
| 技术负责人 | 待指派 | 待指派 | 待指派 |
| 前端负责人 | 待指派 | 待指派 | 待指派 |
| 数据库负责人 | 待指派 | 待指派 | 待指派 |
| 测试与交付 | 待指派 | 待指派 | 待指派 |
| 课程与资源 | 待指派 | 待指派 | 待指派 |
| 教学过程 | 待指派 | 待指派 | 待指派 |
| 评价与学习 | 待指派 | 待指派 | 待指派 |
| 学情统计 | 待指派 | 待指派 | 待指派 |
| AI 适配 | 待指派 | 待指派 | 待指派 |

团队人数较少时，可由项目与产品负责人兼顾文档和原型，由技术负责人兼顾数据库协调，由同一领域负责人承担相邻业务包；测试工作可由成员轮值，但每项关键变更仍须由非作者复核。AI 适配是否在首版投入人力，取决于范围评审结果。

## 5. 开工顺序与完成标准

| 顺序 | 首批任务 | 牵头岗位 | 完成标准 |
| --- | --- | --- | --- |
| 1 | 确认首版范围与团队人员 | 项目与产品 | P/M 分级差异有决定记录；每个工作包有负责人、审核人和验收条件 |
| 2 | 选择并接入若依基础工程 | 技术负责人 | 上游来源、版本和许可证有记录；真实工程构建与基础身份验证通过 |
| 3 | 评审领域、权限、接口与数据 | 领域岗位、数据库负责人 | 课程与教学班授权、状态、提交版本、成绩发布和 SQL 方案经跨岗位评审 |
| 4 | 实现首条端到端业务链路 | 课程与资源、前端、测试 | 教师建课并授权教学班，学生只访问授权资源；正常与越权场景均有验证记录 |
| 5 | 按已批准范围扩展教学闭环 | 对应领域负责人 | 课堂、活动、预习、作业、学情和 AI 能力逐项完成契约、实现与验收 |

## 6. GitHub 协作约定

- 一项可验收任务对应一个 Issue；Issue 写明需求编号或变更来源、负责人、影响模块、验收条件和接口或数据影响。
- 使用短期任务分支提交 PR。PR 说明问题、改动、验证结果、已知限制及相关 Issue；界面改动附原型或截图。`main` 作为稳定主线，由独立审核后合并。
- 跨领域接口变更由提供方与消费方共同审核；权限、成绩和数据库结构变更增加对应责任岗位复核。
- 不提交凭据、真实学生资料、构建产物或未经授权的数据库修改。没有基础工程时，构建和业务测试明确记为“尚不可执行”。

## 7. 待确认事项

- 成员名单、各自专长、兼任方式及独立审核人。
- 首版范围，特别是同步课堂、自建课程、AI 初评和答疑的优先级。
- 若依前后端版本、MySQL 具体版本与部署环境，以及教学数据的使用和保留规则。
- 仓库可见性、许可证、协作者权限及 `main` 分支保护设置。
