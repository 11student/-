# 数据库工作区规范

本目录统一管理数据库设计与脚本。项目已选择 MySQL 作为设计方言；[数据库设计草案](../docs/database-design.md)和 [MySQL 核心表 DDL 草案](mysql-core-schema-draft.sql)供评审。`upstream/ruoyi/` 保存所选若依版本的系统表与 Quartz 表原始脚本，尚未在测试库执行。具体 MySQL 版本和迁移工具仍待确认；教学草案不是正式基线。

## 先设计再建表

以 [架构与数据约束](../docs/architecture.md) 为设计输入，先评审实体归属、关联、状态、快照、提交与成绩版本、唯一约束、索引及保留期限，再将 MySQL 草案整理为正式迁移脚本。

- 若依系统表取自已固定的上游提交；执行前核对脚本来源、适用版本及独立测试库，不手写替代账号权限表或演示数据。
- 教学业务表按九领域标明拥有者，课程内容与教学班发布、模板与实例、AI 建议与正式成绩分别建模。
- 活动并发约束、有效提交唯一性、幂等记录、成绩发布版本需共同设计，不仅依赖前端按钮防重。
- 原题/答案/资源及成员快照要能恢复历史统计，成员退出与撤权不应抹除必要的合法历史记录。
- 不使用真实学生资料作测试数据；敏感字段、附件、日志分别评审访问和保留规则。

## 后续脚本组织

评审通过并确定迁移工具后，再创建 `baseline/`、`migrations/` 及必要的 `test-data/`。基线与增量分开，脚本命名应包含执行顺序和含义，例如日期加领域短语；最终迁移编号规则随采用的迁移工具确定。当前 `mysql-core-schema-draft.sql` 不是正式基线。

每次提交记录适用版本、前置条件、影响对象、数据转换、验证方法、回退或前向修复办法、执行责任人与审核人。迁移须在独立测试库验证后才申请共享环境执行；不可逆数据修改必须有恢复方案。
