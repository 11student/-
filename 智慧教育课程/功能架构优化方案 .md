# 知教｜智慧教育课程平台功能架构优化方案 V2.0

> **文档性质**：产品信息架构与功能范围建议稿（可用于三端侧边导航设计、页面原型、需求拆分和开发排期）  
> **编制日期**：2026-10-21  
> **核心定位**：把 **PPT 讲授工具 + 学习通式教学活动 + 课前课后学习管理 + 轻量学情反馈** 融合成一个连续、简洁的课程教学工作台。教师在一个平台备课、讲课、发活动、看反馈、改作业；学生在同一平台预习、同步跟课、答题、完成作业和补学；管理员只负责组织、授权、治理和运行质量，不代替教师授课。

## 0. 本次优化结论（先定产品边界）

**核心体验不是“菜单齐全”，而是教师打开一门课程就能完成一次真实教学：**

`建课与备课 → 发预习 → 进入课堂 → 放映 PPT → 学生同步跟页 → 一键发签到/随堂题/小作业 → 同屏查看结果 → 发课后作业 → 批改反馈 → 发现薄弱点 → 下次备课`。

相对 V1.0，本次作出以下结构性优化：

1. **以“课程空间”为主容器，课前、课堂、课后为工作流程。** 章节、资源、题库、课堂活动和成绩都从当前课程/教学班上下文进入，不为同一对象建立多个互不连通的入口。
2. **将“上课”设计成独立的沉浸式工作模式，不是普通管理列表页。** 教师讲授画面、学生同步画面、教师私有控制面板分开设计，但使用同一课堂会话和活动状态。
3. **把“预设课堂活动”与“真正发起的课堂活动”区分。** 课前只保存模板/草稿，上课点击发起才创建实际签到或答题，不会误提前向学生开放。
4. **学生端按任务优先，不复制教师功能树。** 学生打开首页即可直接去预习、加入课堂、交作业；智能问答在所学内容旁随时可用，而不是强迫学生先进入“AI 大模型”。
5. **管理员端按职责划分。** 教务管理员管正式课程、教学班、授权组织资源和教学运行；超级管理员管账号权限、AI、技术服务和审计。默认不允许管理员修改教师确认后的学生成绩。
6. **教师可以自己创建课程，但区分“自建课程空间”和“正式教务课程”。** 前者立刻可以备课与试讲；后者与学校的真实教学班和学生名单关联，避免把课程创作与教务学籍混为一谈。
7. **课堂即时掌握情况采用可解释的数据，先做正确率、参与率、知识点薄弱项。** 不把“学生有没有打开 PPT”直接认定为掌握，也不在没有充分评价数据时生成所谓准确的 AI 掌握度分数。
8. **控制首版范围。** 核心先做到“稳定展示和同步 PPT + 预习/签到/答题/作业 + 反馈闭环”；复杂 PPT 动画、视频直播、AI 实时分析、屏幕共享、监考等独立评审，避免项目失去交付焦点。

### 功能标记

| 标记 | 含义 | 是否出现在首版导航 |
|---|---|---|
| `【M0】` | 最小可运行教学闭环，首版**优先打通** | 应有完整可用页面 |
| `【M1】` | 首版完善功能，基础链路打通后建设 | 可逐步上线，不应只放空白菜单 |
| `【M2】` | 二期增强 | 不进入首版默认导航，后期按需显示 |
| `【专项】` | 需要单独评审、授权、预算或安全方案 | 不纳入常规侧栏 |

> **重要说明**：`M0/M1/M2` 是本次为产品落地提出的实施优先级，**不等同于原《需求分析 V2.0》的 P0/P1/P2**。原文把独立签到、随堂答题列为首版，把直播、授课联动列为后续；由于最新产品目标已明确要求 PPT 与学生端同步跟课，本方案建议将“基础课件同步和沉浸式授课”上调至 M0，属于需要评审确认的**产品范围变更**。

# 一、信息架构总则

## 1.1 全平台只建立一套核心业务对象

| 对象 | 作用 | 设计关键点 |
|---|---|---|
| **课程空间** | 课程简介、教学目标、章节知识点、课件、视频、题库等内容资产 | 教师可自建；内容能在多个教学班复用 |
| **正式课程目录** | 学校教务系统认可的课程编码和组织归属 | 管理员维护，可映射一个或多个教师课程空间；不由教师任意改写 |
| **教学班** | 某学期某课程的真实授课对象 | 关联教师、学生名单、学期；预习、签到、作业、成绩按照班级隔离 |
| **教学单元** | 一章/一节/一个知识点关联的教学内容 | 用于组织课前、课中和课后资源，**不强制每项课堂活动都有课次** |
| **备课方案** | 本次想讲的 PPT、讲授资料和已预设课堂活动 | 可保存、复制、预览、复用；尚未发起的活动对学生不可见 |
| **课堂会话** | 一次“开始上课→结束上课”的教学现场 | 对应教学班、教师、备课方案、课件状态和活动记录；允许无备课方案快速开课 |
| **活动模板** | 课前预设签到、答题、小作业等可复用配置 | 仅模板，未激活前不产生学生有效提交 |
| **活动实例** | 一次实际发起、截止并归档的签到/随堂题/任务 | 有唯一 ID、目标对象快照和服务器时间状态 |
| **学习证据** | 视频有效观看、预习答题、签到、随堂题、作业、补学结果 | 来源明确，不能把阅读时长等同于知识掌握 |
| **正式评价** | 教师确认并发布的作业成绩和评语 | AI 建议分不是正式成绩；重做不覆盖原分数 |
| **学情反馈** | 将学习证据按课程、班级、学生、知识点汇总 | 支持教师主动布置下一轮任务，完成教学循环 |

### 1.2 关于“教师自己建课”的两种使用模式

**A. 自建课程 / 试讲模式（建议 M0）：**教师创建课程空间，导入课件、章节和题目；可创建用于预演的试讲课堂。若要邀请真实学生试用，使用**受限的体验教学班/邀请码**（是否允许真实学生加入、可保存哪些数据由学校管理员配置）。不自动生成学籍、正式成绩或教务开课记录。

**B. 正式课程 / 教学模式（建议 M0）：**管理员导入或创建学校课程及正式教学班，分配任课教师、学生；教师把自建课程空间绑定到被授权的正式教学班后，才在学校教学范围发布任务、产生正式学习记录。

> 这一区分是为满足“教师可自行建课”的新需求而增加的方案建议；原 V2.0 仅要求管理员维护正式课程和教学班，二者需要在需求评审中明确。

### 1.3 一级菜单、二级页面和页面内操作的边界

- **一级菜单**：一个稳定的业务领域，建议教师 6 个、学生 6 个、管理员 8 个。
- **二级菜单**：用户确实需要独立进入的页面，例如“预习任务”“随堂活动”“待批改作业”。
- **三级/页面内操作**：上传 PPT、设置截止时间、添加题目、发起签到、查看某道题统计等，放在页面按钮/抽屉/选项卡中，**不再无限拆侧栏**。
- **当前课程与教学班**：除课程列表外，所有教学业务页面使用统一顶部上下文；切换课程/教学班时同步更新范围。
- **消息中心、个人资料、搜索、帮助**：放在顶部栏或头像菜单，不占左侧一级业务导航。
- **“正在上课”**：无论从教师哪个菜单进入，都显示显著的“返回课堂”入口；上课时切换页面不会误结束课堂。

# 二、教师端｜推荐侧边导航（6 个一级菜单）

**核心目标**：让教师用最少跳转完成“建设课程—组织教学—评价改进”。下方 `###` 是一级菜单，编号条目是建议真正出现在侧边栏的二级页面，条目后的短句即该页面需要实现的功能。

## 2.1 教学工作台

1. **教学首页** `【M0】`：显示我的课程、当前教学班、最近课堂、课前/课堂/课后待办、班级重要提醒；不做独立大而全的业务编辑表单。
2. **今日教学与快捷上课** `【M0】`：按课程/教学班查看今天要上的内容，选择备课方案后一键进入上课；无方案也可从课件临时开课；显示进行中课堂入口。
3. **待处理事项** `【M0】`：统一聚合待发布预习、未完成预习提醒、待批改作业、待确认 AI 建议分、待发布成绩、待处理补学；每条直达所属页面。
4. **课程消息与公告** `【M1】`：班级通知、任务提醒、成绩发布提示、教师主动发布公告；站内消息列表可在顶部消息中心复用。

## 2.2 我的课程

1. **课程列表 / 创建课程** `【M0】`：创建教师自己的课程空间，填写名称、封面、简介、教学目标；复制已有课程框架；区分“我的草稿课程 / 正式绑定课程 / 已归档课程”。
2. **课程建设** `【M0】`：维护课程大纲、教学目标、章/节/知识点、教学团队介绍；章节拖动排序；课程概览显示内容建设进度。
3. **课程资源** `【M0】`：上传/预览 PPTX、PPT 转换内容、PDF、视频、图片、教案、文档及授权外部链接；资源分类、版本、标签、知识点关联、授权范围、下架与替换；转换失败可重试/提供 PDF 兜底。
4. **题库与评分标准** `【M0】`：新增/导入单选、多选、判断、简答/论述等题目，关联知识点；编辑答案解析、评分量规、题目版本；供预习、课堂和作业复用。
5. **教学班与课程发布** `【M0】`：查看当前课程绑定的正式教学班、人数、任课教师/协同教师；选择某班开放指定资源或任务，配置起止时间；预览学生看到的内容；申请正式教学班绑定。
6. **课程共享与复用** `【M1】`：本人的资源跨班复用、课程内容复制、与协同教师共享课程编辑权限；校级共享资源按审核规则执行，不等同于公开给所有学生。

**原则**：老师建课程和上传资源在“我的课程”；课前准备只负责把已有内容组合为**本次教学**，避免出现两套资源管理器。

## 2.3 课前准备

1. **授课方案 / 备课包** `【M0】`：选课程及教学班，选择 PPT/教学素材，编排讲授顺序，关联知识点，加入签到/随堂题/小作业的活动模板；提供完整预览、保存草稿、复制上次方案、标为“下次上课”。
2. **预习内容发布** `【M0】`：从课程资源选取 PPT/PDF 指定页、视频片段、阅读材料、导学说明；设置对哪个教学班可见及开放/截止时间；区别“仅教师备课”与“学生课前可见”。
3. **预习任务 / 预习测验** `【M0】`：布置阅读、观看、单选/多选/判断自测与课前小作业；题库选题、设置完成标准、答案公布规则、草稿/定时发布；预习测验默认只进入学情，不直接计入正式作业成绩。
4. **课堂活动预设** `【M0】`：预设签到、随堂题和课堂小作业的模板；设定时长、答案、是否匿名展示汇总、关联知识点及可选 PPT 页码；可按授课顺序排队，一键从模板生成实际活动。
5. **预习学情 / 课前诊断** `【M0】`：查看已完成/未完成名单、完成比例、有效观看覆盖、每题正确率和薄弱知识点；快速提醒、补发、人工核查或有理由豁免；把问题标记为本次重点讲解。
6. **AI 备课助手** `【M2】`：根据当前课程大纲、课件、知识点生成导学、提问题目和备课包草稿；教师确认后才可发布。

**原则**：“预习内容”和“预习任务”可以在一个创建向导中完成，不需要学生在两个不同页面来回找。

## 2.4 课堂教学 ★ 平台最重要的模块

1. **开始上课 / 上课控制台** `【M0】`：选择教学班和备课方案；开始/暂停/结束课堂；查看本次课件、活动列表、参与人数、进行中的活动和课堂即时反馈；支持无预设方案快速上课。
2. **PPT 讲授与内容演示** `【M0】`：平台内分页展示 PPT/PDF，上一页/下一页、跳页、全屏、切换教学资源；把本次 PPT 的当前页、课件版本和公开讲授内容同步到学生端；讲课时快速打开章节关联资料。
3. **学生同步跟课** `【M0】`：展示本班已加入/在线学生数；教师发起跟课状态后学生自动显示教师当前公开课件页；断线重入恢复最新页；明确教师是否允许学生自由翻页和是否允许课后回看。**只是课件状态同步，不等同于摄像头/麦克风直播。**
4. **课堂活动中心** `【M0】`：展示已预设、进行中、已结束的签到/答题/小作业；一键发起活动、查看结果、结束；临时从题库选择题目；确保学生端收到清晰的活动提示。
5. **课堂签到** `【M0】`：动态二维码/短时签到码；开始、截止、迟到判定；实时到场与缺勤统计；教师有理由补签或修正；不采用强制人脸识别和 GPS。
6. **随堂题与即时检测** `【M0】`：教师逐题发起单选/多选/判断题，设置/调整倒计时；学生一次有效提交，实时回收人数、正确率、选项分布；关闭且允许公布后显示答案解析；显示对应知识点的证据和样本量。
7. **课堂小作业 / 随堂任务** `【M0】`：教师预设或临时发布文字题、简答题、短文件任务；学生即时提交，结束后转统一作业提交/批改队列；**不重新开发第二套作业引擎**。
8. **即时学情面板** `【M0】`：教师私有侧栏显示签到情况、答题参与/正确率、各选项分布、待答人数与薄弱知识点；可以决定是否重讲、再发一题或转为课后巩固。仅提供基于当前活动证据的判断，不输出“全班掌握度 93%”等无依据分数。
9. **课堂记录 / 结束归档** `【M0】`：保存会话使用的资源版本、讲授页进度、签到、发题、答题、随堂作业及关键知识点；生成简短课堂回顾，按权限供课后复盘和学生访问。
10. **扩展课堂互动** `【M2】`：投票、抢答、讨论区、随机点名、弹幕、白板批注和笔迹同步，按真实课堂需求逐项增补。
11. **音视频直播 / 录播** `【M2】`：收音、摄像头直播、录制与回看；需要独立评估技术、课堂网络、学生隐私和存储成本。
12. **实时 AI 助教** `【M2】`：课堂内容总结、生成临时提问、解答教师问题；不可绕过教师审核公布正式答案。

**重要 UI 规则**：二级菜单 2–9 是功能入口或“上课控制台”中的页签/工具，不要做成教师上课时必须逐个跳转的 8 个页面。**一旦进入课堂，老师应能在同一个主屏完成放 PPT、发活动、看反馈。**

## 2.5 课后作业与反馈

1. **作业发布** `【M0】`：新建客观、主观、文件、实训成果作业；按班级/授权学生发布，设置开始/截止/分值/次数/补交与解析公布；从课堂错题和题库快速选题，支持草稿和定时发布。
2. **提交与批改** `【M0】`：查看未提交、已提交、待批改、待复核；学生提交版本、迟交与重开留痕；客观题自动判分，主观题教师批改及 AI 建议分；模型失败转人工。
3. **成绩确认与评价发布** `【M0】`：教师逐份/批量复核建议分、得分点及评语；正式确认后再发布；支持按规则撤回、更正并记录理由；**不得把 AI 初评分直接作为正式成绩**。
4. **作业分析与错题复盘** `【M0】`：按题目、教学班、知识点展示正确率、失分原因、学生作业表现；课堂高频错题一键选入课后巩固题组。
5. **补学 / 巩固任务** `【M1】`：选取薄弱知识点，给全班或指定学生布置阅读、视频或练习；学生完成后回流学情，不改变原正式成绩。
6. **课后资料与课堂回顾** `【M0】`：对本班发布可回顾的课件、课堂活动结果及教师补充资料；视频录播只在后续音视频功能具备时开放。

## 2.6 学情分析与教学改进

1. **班级学情总览** `【M0】`：按课程/班/时间查看预习、签到、随堂答题、作业完成、已发布作业成绩及趋势；数据含最新更新时间与统计分母。
2. **学生个人学情** `【M1】`：按有权限的教学班查看学生预习、出勤、作业、错题、补学与历史学习轨迹；对学生提醒和补学留痕。
3. **知识点学习证据** `【M0】`：汇总已关联知识点的预习题、课堂题和正式作业题表现，说明来源、样本量和最近表现；无可靠数据时显示“暂无足够证据”。
4. **课堂/作业复盘** `【M0】`：从课堂某次答题/作业错误查看班级共性问题，追踪到题目和教学单元。
5. **下一轮教学调整** `【M1】`：一键选择薄弱知识点，生成下一次备课方案、预习或补学任务的**草稿**，教师审核后发布；建立“课后→下一次课前”的真实闭环。
6. **基础教学数据导出** `【M1】`：导出授权班级报表；保留筛选条件、统计时点，AI 学情研判/自动建议为 `【M2】`。

# 三、学生端｜推荐侧边导航（6 个一级菜单）

**核心目标**：学生不必理解后台架构，只需清楚“现在要看什么、正在上什么课、要交什么、哪里做错了”。

## 3.1 学习首页

1. **今日待办** `【M0】`：聚合待预习、正在进行的课堂、待签到/答题、即将截止作业、待补学内容；单击直接进入目标任务。
2. **正在上课** `【M0】`：识别本人教学班的进行中课堂，以醒目入口“立即加入”；不必记住课堂编号或找课程树。
3. **学习通知** `【M0】`：班级公告、资料开放、活动开始、作业截止、教师反馈、正式成绩发布；通知可复用顶部消息中心。

## 3.2 我的课程

1. **在修课程** `【M0】`：仅显示已加入/已授权教学班对应的课程卡片、教师、当前进度与待办。
2. **课程主页与章节** `【M0】`：课程介绍、章/节/知识点、已公开课件/视频/导学材料、最近任务与学习进度。
3. **课程学习资源** `【M0】`：根据课前、课中、课后可见性规则阅读 PPT/PDF、观看视频、访问题目解析和拓展资料；被撤回/下架内容不能从旧链接继续访问。

## 3.3 课前学习

1. **我的预习** `【M0】`：按待开始、进行中、已完成、已截止查看预习任务、截止时间与状态。
2. **预习内容学习** `【M0】`：阅读指定页 PPT/PDF、导学资料和视频片段；记录有效进度，允许断点续学；不把“打开过文件”直接标为掌握。
3. **预习测验** `【M0】`：选择/判断/简单自测作答，草稿与提交确认，截止与教师授权后查看答案解析。
4. **预习反馈** `【M0】`：显示是否完成、未完成哪一步、已开放的错题解析与教师补学提醒；预习不足默认提醒，不阻止普通签到。

## 3.4 同步课堂 ★ 学生端最重要的模块

1. **加入课堂** `【M0】`：通过“正在上课”/课程页一键进入，校验所属教学班与课堂状态；显示连接状态，重连后恢复。
2. **跟随老师看课件** `【M0】`：在手机或电脑实时显示当前公开 PPT 页/图片/教学资料；老师翻页即跟随；活动弹出后可清楚返回跟课视图。支持教师配置的自主浏览与课后浏览权限。
3. **课堂签到** `【M0】`：扫码/输入短时码，提交后收到成功/迟到等状态，避免重复签到。
4. **实时答题** `【M0】`：收到题目、倒计时、作答并确认；提交成功有明确反馈；结束且教师公布后查看解析，未公布前不泄露标准答案。
5. **随堂小作业** `【M0】`：在课中接收短答/文件任务并提交；看到已提交及待批改状态，结束后仍可在作业记录查看结果。
6. **我的课堂记录** `【M0】`：本人签到、答题、已公布反馈、允许开放的课件和课后任务；不能查看其他学生的个人成绩或隐私。
7. **课堂提问/讨论** `【M2】`：举手、投票、提问、讨论；首版不用为了“热闹”增加复杂聊天模块。

## 3.5 课后学习

1. **我的作业** `【M0】`：待提交/已提交/待批改/已发布结果；展示截止时间、任务内容、知识点和提交规则。
2. **作答与提交** `【M0】`：客观题、文本题、文件/实训成果提交；草稿保存、上传进度、提交时间和版本提示，按规则改交/补交。
3. **评价与反馈** `【M0】`：查看教师已发布的正式得分、评语、失分点和解析；未发布时只显示进度，不展示隐藏答案。
4. **我的错题本** `【M0】`：汇集已公布答案的课堂题与正式作业错题，按课程/知识点归档、重做和查看解析；重做不得覆盖原始成绩。
5. **补学与巩固** `【M1】`：查看教师定向布置的补学资料和练习、完成情况及反馈。
6. **课后课堂回顾** `【M0】`：查看允许回顾的课件页、课堂活动与教师补充资料；后续录播功能单独开放。

## 3.6 我的学习与智能答疑

1. **个人学习概览** `【M1】`：只统计本人的课程进度、预习、出勤、作业与知识点表现，不与班级同学做不适当公开排名。
2. **学习轨迹 / 学习报告** `【M1】`：本人按时间查看学习记录、导出个人报告；数据访问受当前授权控制。
3. **课程 AI 答疑** `【M1】`：结合本人有权限访问的课件、知识点，提供带来源的答疑；对未公布答案的作业只作思路引导，不调用隐藏答案。
4. **错题 / 课件一键讲解** `【M1】`：从错题和知识点处打开同一 AI 答疑抽屉，无需在多个菜单间切换。
5. **个性化学习推荐** `【M2】`：根据可靠的学习证据推荐已授权资源，避免无依据的学习能力标签。

> **学生端移动设计**：首页、预习、跟课、作业四条路径必须优先适配手机浏览器。手机底部导航可简化为“首页｜课程｜课堂｜作业｜我的”，侧边栏结构仍用于桌面或管理视图。

# 四、管理员端｜重新设计的导航与边界（8 个一级菜单）

**核心目标**：保持课程教学运转、数据可信、资源合规、权限安全，**而不是给管理员提供“替老师上课”的操作界面**。

- **教务管理员**：只处理授权学院/专业/学期/课程/教学班的组织、开课、内容审核、教学运行与统计。
- **超级管理员**：主要负责账号、角色、数据权限、模型/配额、系统参数、故障和日志。可查看经授权的汇总，但敏感学生原文及个人成绩不是“超级管理员默认随便看”的信息。
- 页面可复用一个后台，按照 `功能权限 + 数据范围 + 操作权限` 决定展示、查询、下载和修改范围。

## 4.1 管理工作台

1. **教学运行总览** `【M0｜教务/超级】`：按授权范围统计课程、教学班、开课教师、学生、进行中任务、课堂数量、资源数和作业处理情况。
2. **管理待办** `【M0｜教务/超级】`：待审核资源、待绑定课程/教学班、异常课堂同步、待处理的教务数据导入错误及教学协调事项。
3. **异常与服务概况** `【M1｜教务/超级】`：显示课堂连接/课件转换异常数、作业处理异常及 AI 服务告警摘要；不直接展示学生私密答题原文。

## 4.2 组织与人员

1. **学校组织架构** `【M0｜教务】`：学院、专业、学期、教学相关组织的层级维护/导入，校验归属和授权范围；不建设完整学籍业务。
2. **教师与学生信息** `【M0｜教务】`：查询/导入学校必要的教师与学生基础信息，维护任教关系、教学班成员关系、账号绑定；提供批量导入失败明细。
3. **教务数据导入** `【M0｜教务】`：统一导入课程、教学班、教师、学生关联数据，字段映射、重复/冲突校验、差异预览、回滚或修正记录。
4. **组织变更记录** `【M1｜教务】`：教学班调班、退课、协同教师调整及历史影响提示；历史参与人数按活动发布时快照，不随之后换班被偷偷改写。

## 4.3 课程与教学班

1. **正式课程目录** `【M0｜教务】`：学校课程编码、名称、开设学院、学期、状态，导入或创建学校正式课程记录；避免与教师自建课程空间混为一谈。
2. **教师自建课程备案与关联** `【M0｜教务】`：查看教师申请绑定的课程空间，确认归属/复用关系；处理重复课程、课程交接和正式教学班绑定申请。
3. **教学班管理** `【M0｜教务】`：创建/导入正式教学班，指定课程、学期、主讲及协同教师、学生名单、开班/结课状态。
4. **教学授权与协同授课** `【M0｜教务】`：授权教师可使用的课程/教学班及协同权限，区分查看、编辑、发任务、上课、确认成绩、导出；超出范围必须拒绝。
5. **课程归档 / 交接** `【M1｜教务】`：学期结课、资源复用、停课与转交、按规定保留历史学习记录；访问仍以当前权限为准。

## 4.4 教学资源与内容治理

1. **全校资源总览** `【M0｜教务】`：按授权课程查看 PPT、PDF、视频、教案、题目、知识点和知识库索引的数量与状态。
2. **资源审核与下架** `【M0｜教务】`：依据学校审核策略审查待公开/申请共享的资源，批准、退回、下架并记原因；老师私人备课草稿不做无意义的逐文件审批。
3. **共享题库与评分标准** `【M1｜教务】`：审核校级共享题、评分量规、知识点关联；教师课程私有题库在授权范围内自主管理。
4. **课程知识库治理** `【M1｜教务/超级】`：查看授权课程的索引状态、资料来源和版本；下架资料同步退出 AI 检索，排查越权知识片段。
5. **资源存储与文件安全** `【M1｜超级】`：文件类型/大小限制、空间配额、安全检测、PPT 转换失败、资源清理与备份策略。

## 4.5 教学运行管理

1. **课前任务运行** `【M0｜教务】`：课程/教学班预习发布情况、应参与人数、已完成状态、超时和异常；原则上只看汇总与必要授权明细。
2. **课堂运行与服务状态** `【M0｜教务/超级】`：当前开课情况、课程/教学班、上课时间、课件同步服务健康度、签到和答题是否正常；技术维度可查看连接错误和重试情况，不是监视学生屏幕。
3. **作业与批改运行** `【M0｜教务】`：查看作业发布数、提交量、待批改、AI 初评和教师正式发布状态；管理员可协调但**不默认代教师评分或更改成绩**。
4. **异常处理台账** `【M1｜教务/超级】`：处理导入失败、课件无法转换、课堂同步中断、签到争议、提交失败等；对涉及成绩/签到的业务修正由相应授权教师执行并留痕。
5. **运行通知与协调** `【M1｜教务】`：学校/学院级公告、异常处理提醒与回复记录；不建立和课程通知平行的第二套消息系统。

## 4.6 教学质量与反馈

1. **教学质量概览** `【M0｜教务】`：预习完成、课堂参与、签到、作业提交与已发布成绩的分项趋势；清楚注明分母、样本和统计窗口。
2. **课程/教学班分析** `【M1｜教务】`：按学院/课程/教学班查看不同教学环节完成情况及波动，必要明细另授权，不做无依据的跨教师排行榜。
3. **学情规则配置** `【M1｜教务/超级】`：管理作业提交率、课堂参与、缺勤等规则阈值，保留生效时间和版本；不能凭单次答题把学生划为风险人群。
4. **学情预警与协调** `【M2｜教务】`：候选预警→人工核实→通知教师→处理反馈→复核关闭；AI 只提供解释和建议。
5. **报表与质量报告** `【M1｜教务】`：导出有权限的基础数据表；自动生成综合教学质量 PDF 报告为 `【M2】`。

## 4.7 用户与权限

1. **用户账号** `【M0｜超级】`：教师/学生/管理员账号创建或导入、启停、重置凭证、会话撤销及基本账号状态。
2. **角色与菜单权限** `【M0｜超级】`：教师、学生、教务管理员、超级管理员预置权限和具体操作点配置；菜单隐藏不能代替后端权限检查。
3. **数据范围授权** `【M0｜超级】`：学院/专业/学期/课程/教学班和特殊导出权限管理；教务管理员不能自行扩大组织范围。
4. **敏感数据访问审核** `【M1｜超级】`：成绩详情、答题原文、学习轨迹和批量导出需明确用途、授权与操作留痕。

## 4.8 平台设置与 AI 服务

1. **平台基础参数** `【M0｜超级】`：上传限制、时间与学期默认值、资源审核策略、任务与作业通用规则、通知设置。
2. **课堂技术配置** `【M0｜超级】`：PPT 转换服务、课件可用状态、同步服务连接、会话恢复、课堂错误告警与基本监控。
3. **AI 模型与配额** `【M1｜超级】`：模型接入参数、加密存储密钥、超时降级、全校/角色/场景用量限制、调用任务状态；AI 失效不影响人工正常教学。
4. **操作日志与 AI 审计** `【M0｜超级】`：账号登录、权限变更、资料审核、活动修正、成绩确认/撤回、导出和 AI 调用记录；日志查看权限和保留期限可配置。
5. **数据备份与生命周期** `【M1｜超级】`：数据库/附件备份恢复、数据保留与删除/匿名化、安全导出和权限检查。
6. **外部系统集成** `【M2｜超级】`：学校统一认证、智慧树、超星、章鱼教学服务器等；没有接口授权及测试环境不承诺双向同步。
7. **考试监考 / 硬件设备** `【专项】`：摄像头监考、AI 人脸识别、代码执行沙箱和复杂考试管理，作为独立需求，不放入首版侧栏。

> **建议**：教务人员登录后不显示“用户与权限、平台设置与 AI 服务”的超管专属页面；超级管理员登录可侧重系统健康、权限和服务治理。二者共享组件和数据服务而不重复建设两套后台。

# 五、课堂主界面：最值得投入 UI 设计和工程资源的页面

**不要把“课堂签到”“课堂答题”“PPT 页面”“实时统计”做成上课时需要反复跳转的四个独立页面。** 把这些能力整合成**一间实时课堂**，导航只是进入方式。

## 5.1 建议的三种屏幕视图

### A. 教师私有控制台（PC/笔记本）

- **中央主区域**：当前 PPT/PDF/教学素材，支持翻页、跳页和切换素材。
- **左侧轻量区域**：章节、课件缩略图、授课方案时间线、预设活动队列。
- **右侧实时反馈**：在线/已加入人数、签到、当前题目已答数、正确率、选项分布、关联薄弱知识点；可收起。
- **底部悬浮工具条**：上一页/下一页、投影、发布签到、发起随堂题、课堂小作业、查看活动、结束课堂。
- **教师私有数据**：备注、参考答案、正确选项、未公布成绩、学生具体明细只能在私有控制台出现，**绝不可自动同步到投影或学生跟课端**。

### B. 教室投影 / 公开大屏

- 只显示**教师明确公开的课件、题目、倒计时和经教师允许公开的匿名统计**；不显示管理按钮、学生姓名/成绩、AI 私有建议、教师备注或未公布答案。
- 优先支持浏览器全屏投影；若仅单屏，教师切换回私有控制台时避免意外把机密内容投到公开画面；有条件时支持扩展屏/独立投影窗口。

### C. 学生跟课端（手机优先）

- 默认显示老师当前公开 PPT 页以及“正在授课/正在答题/课堂已结束”状态。
- 教师发起新活动时，通过清晰提示进入签到或答题；提交结束后自动返回当前页，不丢失跟课进度。
- 网络断开后明确标识；重连从服务器获取最新课堂状态和当前页，不靠旧的浏览器缓存猜测。
- “能看课件”与“允许自由翻阅/下载/课后查看”分开授权。

## 5.2 上课会话的基本状态

```text
备课草稿 → 可用于上课
                   │
                   ▼
              课堂进行中
             ┌────┼────┐
             │    │    │
          课件同步 签到实例 答题/小作业实例
             │    │    │
             └────┴────┘
                   ▼
              结束 / 归档
                   ▼
       课堂复盘、正式作业、学情反馈
```

**建议**：M0 建立课堂会话记录以承载 PPT 页码同步和活动时间线；但保留“教学班内独立签到/独立发题”接口，不强制每个活动必须依附课堂会话，以兼容原 V2.0 的独立活动需求。

## 5.3 关键课堂场景与应有行为

| 场景 | 正确体验 |
|---|---|
| 教师第一次进课堂 | 选教学班 → 选择 PPT/备课方案 → 点击开始上课；无需先配置 10 项复杂参数 |
| 教师翻到第 8 页 | 投影与已加入的学生端显示相同公开页；教师备注/隐藏答案不被广播 |
| 预设“签到” | 课前只存在模板，上课一键激活后学生才可扫码/输码 |
| 正在答题 | 教师看到已答/未答与正确率，学生看到题目与倒计时；关闭前不泄露答案 |
| 发起另一题 | 同一个教学班同一时刻只有一个有效进行中的实时题，避免学生界面冲突 |
| 学生中途掉线 | 重连取得最新页、活动状态及本人已提交结果；已成功提交的答案不重复入库 |
| 学生更换手机 | 后端依据课堂会话与用户身份恢复本人状态，不依赖单设备本地数据 |
| 教师结束课堂 | 活动停止、提交规则按服务端状态生效，资源与课堂结果归档，并可生成下一步任务 |
| 课件渲染异常 | 明确显示转换状态和失败原因，提供 PDF/静态页预览兜底，不能临上课才发现完全无法打开 |
| 网络临时中断 | 已开启的活动状态由服务器维护；恢复后以服务端记录为准，必要时教师按权限手动补救并留痕 |

## 5.4 PPT 能力范围建议

- **M0 必做**：上传 PPTX/PDF → 后端转换为可分页同步展示的内容 → 预览 → 全屏 → 上下页/跳页 → 学生跟页 → 允许/禁止课后访问。
- **M1 考虑**：重点页标注、页内跳转、课件缩略图、关联题目提醒、双屏讲者视图体验优化。
- **M2 再评估**：尽可能还原原生 PowerPoint 动画、音效、复杂嵌入对象；同步手写板书、连续屏幕视频推流。
- **不应误导的地方**：用幻灯片图片/静态页同步，**不等于实现了完整的 PowerPoint 软件编辑器**，不得对动画/宏/字体/嵌入视频效果作无法验证的兼容承诺。

# 六、课前—课中—课后：必须真实发生的数据联动

## 6.1 教师的一次完整教学

```text
[第一次建课]
教师自建课程空间 → 导入 PPT、资料、题库 → 创建章节知识点
                                   │
正式教学场景：管理员授权正式教学班 ──────┘
                                   ▼
[课前]
组织本次备课包 → 发布预习资料/预习任务 → 学生预习与自测
                                   ▼
教师查看预习薄弱点 → 修改本次讲授重点 + 预设签到/题目
                                   ▼
[课中]
教师开始课堂 → 演示 PPT → 学生同步跟页
         ├─ 发起签到 → 到课与迟到记录
         ├─ 发起随堂题 → 参与人数/正确率/选项分布
         └─ 发起课堂小作业 → 学生提交
                                   ▼
[课后]
课堂复盘 → 发布作业 → 学生完成 → AI 建议批改/人工批改
                                   ▼
教师确认正式反馈 → 学生看错题/完成补学 → 更新学情
                                   ▼
[回到下一次课前]
教师从薄弱知识点直接新建下一次预习/课堂练习草稿
```

## 6.2 统一作业与活动底层能力，避免重复开发

| 类型 | 何时配置 | 何时对学生生效 | 提交/评价 | 数据用途 |
|---|---|---|---|---|
| 预习任务 | 课前 | 教师发布/到开放时间 | 有效阅读观看、自测 | 课前诊断，不默认计入正式成绩 |
| 签到 | 课前模板或课中临建 | 教师实际开启 | 一次有效签到、可有理由修正 | 出勤证据 |
| 随堂答题 | 课前模板或课中临建 | 教师实际开启 | 实时单次提交、客观题规则判分 | 即时理解检查与知识点分析 |
| 课堂小作业 | 课前模板或课堂临建 | 教师实际发布 | 复用统一提交和批改能力 | 课堂形成性评价 |
| 课后作业 | 课后或课前预设 | 教师发布/到开放时间 | 规则判分、AI 建议、教师确认 | 正式作业记录和错题本 |
| 补学/巩固 | 课后分析后 | 教师向选定对象发布 | 学习与练习反馈 | 下一轮教学依据，不覆盖旧成绩 |

### 6.3 信息回流最少需要做的三件事

1. 预习题和随堂题必须关联**知识点 ID**，否则所谓“哪里没掌握”只能停留在作业/题目维度。
2. 课堂反馈除了统计图表，还要提供“**加入本次课后巩固/下节课备课**”的快捷入口。
3. 学生重做与补学形成新的学习记录，但保留原始提交、正式成绩与评价版本，避免影响历史统计。

# 七、首版功能边界、风险与取舍

## 7.1 M0｜优先实现的最小教学闭环

**必须真实可用，不以静态演示按钮代替：**

1. 用户登录、教师/学生/管理员基础身份与课程/教学班授权。
2. 教师自建课程空间、上传/预览 PPT/PDF、章节与知识点、正式教学班关联。
3. 预习内容发布、学生预习测验、教师查看预习完成与知识点错题。
4. 创建本次授课方案并预设签到/随堂题；允许无方案快速上课。
5. 教师在网页开始课堂、放映 PPT、控制翻页；学生在浏览器/手机同步跟课；投影与教师私有数据隔离。
6. 一键发起签到、随堂题、课堂小作业；学生正常参与、有效提交；教师看实时人数/正确率/选项分布。
7. 课堂结束归档；老师发布课后作业；学生完成和提交；教师人工批改及必要的客观题规则判分。
8. 正式成绩由教师确认/发布；学生查看评价、错题重做；教师看基础班级学情与薄弱点。
9. 管理员能导入/维护正式课程、教学班、成员与任课权限，审核资源，查看汇总的教学运行及必要审计。
10. 课堂关键场景支持重复点击幂等、断线重连、权限隔离和失败提示。

## 7.2 M1｜把首版做完整、做得好用

- 作业 AI 建议初评、教师复核及异常转人工；评分量规与版本管理。
- 丰富的学生个人学情、教师补学任务、学情结果跳转下次备课草稿。
- 课程共享、模板复用、双屏讲者视图优化、课堂更丰富的教学轨迹。
- 管理端基础报表导出、资源内容治理、AI 服务配置和更细的数据授权。
- 学生按课程资料进行 AI 答疑，必须校验知识库范围和隐藏答案隔离。

> 原《需求分析 V2.0》将 **AI 初评（配合教师复核）**、个人学情和学生文本答疑放入建议首版 P0；本方案出于“先保证真实授课主链路”的实施节奏，把部分能力排到 M1。**这不是否定原需求，而是需要项目负责人确认的新优先级建议**。如已有团队和接口条件，也可将这些能力并入首版交付。

## 7.3 M2｜二期增强

- 课堂投票、讨论/举手、抢答、白板、随机点名、音视频直播和录播。
- AI 自动备课、课堂实时助教、AI 学情研判、个性化推荐与自动预警处置闭环。
- 深度 PPT 动画还原、完整 PowerPoint 编辑能力、多方实时音视频。
- 校内统一认证及第三方平台数据对接（取决于授权与接口条件）。

## 7.4 不应在本项目首版做的东西

- 全校学籍管理、正式考试总评审批、完整题库考试监考系统。
- 人脸识别签到、持续 GPS 监控、学生屏幕监控、自动判定作弊。
- 代码执行沙箱与自动判题平台、复杂实训课程运营、证书考核体系。
- 没有数据依据的“AI 学习能力百分比”、全校学生公开排名、教师教学质量绝对分数。
- 未获得授权时承诺与学习通、智慧树、章鱼教学服务器的双向同步。

# 八、必须明确的业务与安全规则（UI 不可省略）

1. **课程与教学班分离**：课程是内容容器，教学班是学习活动与学生数据的归属。一个课程可被多个班使用，资源按班级另行发布。
2. **教师自主建课但不可越权操作正式学生**：自建课程、体验教学班、正式课程与教务教学班的数据范围分清楚，邀请加入要有授权流程。
3. **课堂会话由服务器判定状态**：开始/结束、当前页和活动开关以服务端为准，重连按最新版本/序号同步，避免教师和学生各看各的。
4. **活动模板不是活动实例**：未正式开启的签到/实时题学生不可提前作答；同一教学班同一时刻最多一个进行中的签到和一道进行中的实时题。
5. **学生提交必须防重复**：重复点击、弱网重试不可产生两份有效签到/答题/作业提交；教师补答、补签要写原因、留修订历史。
6. **教师私密内容永不自动投影**：讲稿、参考答案、学生姓名、未公布成绩和私有 AI 建议与公共大屏/学生公开内容严格隔离。
7. **答案和成绩遵循发布时点**：随堂题结束且授权后才显示解析；AI 建议分须由教师复核确认再转为正式成绩；撤回/更正需追溯。
8. **预习门槛默认提醒不封锁**：若启用具体活动的前置条件，必须显式提示学生并允许教师按规则豁免。
9. **统计必须注明口径**：参与率分母、目标成员快照、统计时间、有效样本和最近更新时间要一致；缺少证据显示“暂无数据”，而非“0 分掌握”。
10. **授权贯穿所有接口**：除了菜单，还需验证页面详情、资源下载、AI 检索、课堂实时消息、报表和导出；退课/撤权后不继续开放资源。
11. **AI 不能越权**：仅检索用户有权查看的课程资料，未公布的标准答案及其他学生记录不得进入学生答疑上下文；调用有额度、日志和人工降级。
12. **学生数据与课堂记录有保留期限**：资源版本/任务快照/成绩历史的必要存档和原始附件、日志的留存规则分离，不能默认永久保存所有数据。

| 课程答疑 | 学生学习与智能答疑；教师相关页面内工具 | 不再作为教师频繁跳出的独立主菜单 |
| 学院架构/专业架构/账号与角色 | 组织与人员 / 用户与权限 | 教务组织和系统身份权限拆清 |
| 资源审核/题库知识库/全校作业/统计预警 | 内容治理 / 教学运行 / 教学质量 | 按“治理—监管—反馈”分工，避免管理员业务杂糅 |
| 系统配置/审计与 AI 日志 | 平台设置与 AI 服务 | 超管负责模型、配额、课堂同步可靠性和审计 |

# 十、验收时至少跑通的 8 条端到端场景

1. **创建课程**：教师创建课程空间，上传 PPTX/PDF，建立知识点并预览；绑定授权的正式教学班后能向该班发布内容；其他班未授权不能打开。
2. **预习链路**：教师布置视频/课件/预习题 → 学生完成 → 教师看到完成状态和错误知识点 → 可据此调整备课内容。
3. **同步上课**：教师选班开始课堂并翻 PPT → 投影/学生端显示当前公开页 → 中途新加入的学生看到最新页 → 教师私有备注不可见。
4. **课堂签到**：教师启用预设签到 → 本班学生签到成功、外班被拒绝 → 重复请求不新增记录 → 教师补签必须记录原因。
5. **实时答题**：老师发一道题 → 学生提交 → 教师实时看到已答数及选项分布 → 关闭并授权后公布答案 → 学生重连不会多次提交。
6. **课堂小作业**：老师课堂一键发小作业 → 学生文字/附件提交 → 课后在统一作业批改队列中查看，学生可回看提交状态。
7. **课后闭环**：教师发正式作业 → 学生提交 → 客观题判分/主观题建议评价 → 教师确认发布 → 学生查看反馈和错题 → 教师把薄弱知识点转下一次预习草稿。
8. **管理员边界**：教务管理员只能看到其授权学院/课程统计；超级管理员可调整配额/权限并有审计；越权获取他班作答、AI 隐藏答案和未授权文件一律拒绝。

# 十一、建议的开发顺序（按使用价值而非菜单先后）

| 顺序 | 最先建设的能力 | 为什么先做 | 可验证的产物 |
|---|---|---|---|
| 1 | 身份、课程空间、教学班关联、课件导入/转换 | 决定所有页面的数据归属和访问权限 | 老师能创建课程，学生能看授权课件 |
| 2 | 课堂会话、PPT 展示/同步、公开投影与学生跟课 | 产品核心差异化能力 | 真实两端跟页、断线重进不乱页 |
| 3 | 活动模板、签到、实时题、即时统计 | 体现“PPT 与学习通功能合一” | 教师讲课时能一键发题且同屏看数据 |
| 4 | 预习任务与课前诊断 | 用课前结果指导课堂讲解 | 预习数据可查、错题关联知识点 |
| 5 | 作业提交、批改、发布、错题归集 | 完成课后环节 | 一份课后作业从发布到评价闭环 |
| 6 | 班级/个人学情、下一轮任务入口 | 真正构成教学循环 | 从薄弱知识点新建下一次任务草稿 |
| 7 | AI 初评/答疑、资源共享、报告、丰富互动 | 降低初期技术依赖与集成风险 | 在稳定主流程上逐步加值 |

> 首版开发过程中应尽早做 **真实设备的教师 PC + 学生手机同步试验**，尤其要验证课件转换质量、课堂网络、多人并发提交和投影隐私隔离，而不是只看原型截图是否美观。

# 十二、来源与产品建议的区分

### 原《智慧教育课程需求分析 V2.0》已明确的范围和约束

- 三端：教师、学生、管理员（细分超级管理员和教务管理员）。
- 课程与教学班的区别；资源跨班复用但发布范围按教学班；章节/知识点组织。
- 课前课程资源、预习任务、预习完成与自测，课中独立签到/随堂答题，课后作业、AI 建议初评、教师确认、错题、学情和通知。
- 三阶段数据回流与权限隔离；统计可核查、异常留痕；直播与多种实时 AI 能力后置；课程总评审批、学籍和监考不属于首版常规范围。

### 本方案根据新的实际授课目标主动提出的优化/范围调整

- **新增/提升**：沉浸式授课控制台、PPT 教师/投影/学生三视图、同步页状态与断线恢复、课堂会话、备课方案和活动模板、课堂小作业与统一提交引擎复用。
- **调整**：教师自建课程空间支持自助创作；正式教务课程和教学班仍需授权；如提供试讲邀请码，应明确真实学生加入和数据留存规则。
- **导航优化**：资源/题库集中到课程空间，教学环节导航只负责具体教学活动，管理员不重复教师执行型功能，学生首页突出实时课堂和待办。
- **实施建议**：部分原 V2.0 建议首版的 AI 能力可根据团队资源从 M0 调整至 M1，但若学校已明确承诺范围，应先经需求评审同意，不能直接删减。

**最后的产品判断**：宁可先把“老师在平台上放 PPT、全班手机同步、发一题立即看到对错、课后承接作业和错题”这条链路做得稳定、好用，也不要首版堆叠证书、监考、直播、综合 AI 指数和大量后台菜单。课程教学主链路一旦做顺，其他能力才有真正的价值。
